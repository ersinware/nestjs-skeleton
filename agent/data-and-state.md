# Data & State

- Share aggregate invariants through opt-in bases, never universal `AggregateRoot`. Valid idempotent requests for the existing state are no-ops without jobs; invalid transitions fail.
- Admin and User use the canonical job-producing aggregate-root bases.
- `SoftDeletableAggregateRoot`: concrete mutators call `assertNotDeleted`, except repeat-safe `markAsDeleted`. Writers load only non-deleted aggregates; attempted mutation of a deleted aggregate is `SystemException`.
- Modules own their tables/Drizzle definitions in same-named PostgreSQL schemas; no central table registry. Exception: core owns/writes `audit.audit`; `audit-trail` reads its barrel-exported table via replica. Keep `drizzle.config.ts` discovery and `schemaFilter` aligned with application-owned schemas.
- No cross-module JOINs or synchronous transactions. Cross-context references are soft UUID links without foreign keys; compose reads in memory via facades ([Module Isolation](architecture.md#module-isolation)), reconcile mutations via durable jobs ([Jobs & Messaging](jobs-and-messaging.md#jobs--messaging)).
- Wrap related DB writes in `ITransactionPort.run`; the primary proxy uses ALS, and nested calls join without savepoints. Await writes sharing a transaction sequentially so a rejection cannot end it while another write is pending; use `Promise.all` only for independent work outside a shared transaction. Propagate errors; keep DB work inside the callback and network/pipeline calls outside. Context isolation has no runtime guard.
- Row IDs: UUID v7, generated by creating command handlers for aggregates and schema `$defaultFn` for core tables without aggregates; never `gen_random_uuid()` for application-owned rows.
- Application-owned listings use `id DESC`; audit uses `occurredAt DESC, id DESC`. Index application-owned filters/order. Pg-boss DLQ listings use `created_on DESC, id DESC` because queue-generated IDs need not be time ordered; verify their query plan against the pg-boss-owned indexes.
- Keep sessions in Redis, never local memory.
- Adapters select `TOKEN_DATABASE_CLIENT` for writes, write-decision reads, and cacheable queries; `TOKEN_DATABASE_REPLICA_CLIENT` for lag-tolerant presentation reads. A configured replica bypasses ALS; missing/empty `DATABASE_REPLICA_URL` aliases the primary proxy.
- Budget PostgreSQL connections across the primary, configured replica, and each independent pg-boss pool per process, multiplied by the maximum instance count.

### Adapters

- Keep module aggregate writers and query readers separate: writers load/save aggregates through one write port each; readers return read-models. Read-only modules need no writer ([CQRS](architecture.md#cqrs)).
- Group source readers by source and relevant thin ports, never one adapter per port. Keep unrelated sources out; composition adapters may combine sources ([CQRS](architecture.md#cqrs)). Primary/replica readers: `<module>-reader.adapter.ts` / `<module>-replica-reader.adapter.ts`.
- Core adapters follow capabilities (`cache`, `cache-health`, `cache-cleaner`), not forced reader/writer pairs; split divergent responsibilities into meaningful sub-concepts.
- `core/redis` owns factories/classifiers; cache/session own connections and failure policies.
- Aggregate rows have `version integer`; `AggregateRoot.version` stays at loaded version (new = 0), never incremented in memory. `save()` conditionally upserts: insert loaded version or update to loaded+1 WHERE stored=loaded. Zero rows → `ResourceConflictException(CONCURRENT_MODIFICATION)`; affected endpoints document 409. No row-lock transaction across load→save/hashing. Independent append-only inserts need no row version; decisions based on other mutable state still need protection. Single-statement updates need no version only when independent of previously read mutable state and enforcing all required conditions atomically.
- Writers translate known owned constraint violations to taxonomy exceptions with `{ cause }`; classifiers live in `src/core/database`. Other DB errors: `throw translateConnectionFailure(error)` → `DependencyUnavailableException` for connection failures, otherwise unchanged. Raw health pings/test cleaners are exempt ([Exceptions](exceptions.md#exceptions), [Dependency Outages](observability.md#dependency-outages)).
- Request-path cache failures recognized by `isRedisUnavailable` fail open: `get: null`, `set/delete: no-op`; others propagate unchanged. Durable job eviction uses `ICacheEvictionPort`; failures propagate to pg-boss for retry ([Jobs & Messaging](jobs-and-messaging.md#jobs--messaging)). Empty keys throw `SystemException`; serialization/programming errors propagate. Session Redis: [Session Versions & Failure Semantics](security-and-sessions.md#session-versions--failure-semantics). Detached-write reporting: [CQRS](architecture.md#cqrs); awaited failures: [Exceptions](exceptions.md#exceptions).
