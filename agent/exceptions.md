# Exceptions

- Project-thrown failures use the transport-neutral taxonomy in `src/shared/exception`, never Nest HTTP exceptions. Framework-raised HTTP errors remain supported; health passthrough: [Health Probes](http.md#health-probes).
- Catch only contract-defined cases; rethrow others unchanged. Translation/fail-open: [Adapters](data-and-state.md#adapters); best-effort cache failures: [CQRS](architecture.md#cqrs); delivery failures: [Jobs & Messaging](jobs-and-messaging.md#jobs--messaging).
- Classify taxonomy exceptions with `isExceptionOfKind`; recognize the taxonomy with `isAppException`, never `instanceof`. Native/framework/driver errors without `kind` may use `instanceof`.
- Dependency classifiers inspect `cause` chains and recognize only known availability failures; authentication, configuration, protocol, programming, and unknown failures must not become dependency outages.
- Keep generic message enums beside their exception classes; never add module-specific vocabulary there. Inline single-use messages; shared use-case messages belong in `command.ts`/`query.ts`, other messages follow [Placement & Naming](architecture.md#placement--naming).
- Business-rule ownership: [Data & State](data-and-state.md#data--state). Expected business refusals use appropriate taxonomy kinds; broken internal paths use diagnostic `SystemException`.
- Optional `AppException.audit` carries refusal action/reason, independent of kind and diagnostic `context`; neither reaches clients. Handlers wrap every aggregate call (including factories, validation, and finalization) in `try/catch`, even if it currently carries no audit. Check `isExceptionWithAudit`, await audit with `markExceptionAsAudited` when present, then rethrow the same error; audit failures propagate. Metadata alone never suppresses audit. Durability: [Audit](observability.md#audit).
- Preserve the caught value in `cause` when wrapping or translating errors, including 4xx and helper-created exceptions. `context` follows `ExceptionContext`, belongs only to system/unexpected faults, and stays independent of logger/audit vocabulary. Neither reaches clients.
- Throwers do not log; reporting belongs to the handling boundary ([Observability](observability.md#observability)). Refusal evidence: [Audit](observability.md#audit).
- `GlobalExceptionFilter` alone maps taxonomy to HTTP through exhaustive `KIND_TO_STATUS` and `ErrorDefaultDto`; unknown errors become 500. Mask 404/5xx messages with their shared defaults; health passthrough: [Health Probes](http.md#health-probes).
- HTTP filter reporting: 503 silent; other 5xx error-log + Sentry, preserving diagnostic context; 403 audit `ACCESS_DENIED` unless the same exception was durably audited in the current request; others silent. Read context only for reported 5xx; never downgrade system faults to warn/info.
